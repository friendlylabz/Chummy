# Building and testing

## Prerequisites

- [Rust](https://rustup.rs) (version pinned in `rust-toolchain.toml`) and
  Node.js 22+.
- Linux: `libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev
  libxdo-dev libssl-dev libdbus-1-dev build-essential`, plus a Secret
  Service (GNOME Keyring or KWallet) to save API keys.
- macOS: Xcode Command Line Tools. Windows: C++ Build Tools and WebView2.

## Commands

```sh
npm install
npm run tauri dev        # the app, with hot reload of the UI
npm run dev              # the UI alone in a browser (IPC uses mocks)
npm run tauri build      # installers: .msi/.exe, .dmg/.app, .deb/.rpm/.AppImage
npm run icons            # app icons from assets/app-icon.png
```

Checks (CI runs all of them, and so should you before committing):

```sh
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
npm run check            # svelte-check, warnings fail
npm run test:ui          # small TypeScript tests in ui/src/lib/*.test.mts
npm run build            # Vite build
python3 -m unittest discover -s crates/local/engine
python3 crates/flow/templates/make_templates.py   # then git diff should be empty
```

## The tools' Python

Tools run on CPython built for WebAssembly, bundled with the app.
`scripts/build-wasi-python.sh` builds it from python.org's source (pinned
SHA-256 and Sigstore signature, Linux x86_64, about 5 minutes) into
`wasi-python/python-wasi.zip`. Without it the app builds but can't set up
tools. To run the sandbox tests against it:

```sh
CHUMMY_TEST_PYTHON_ZIP=$PWD/wasi-python/python-wasi.zip cargo test -p chummy-tools
```

Container tests need Docker or Podman and `CHUMMY_TEST_DOCKER_IMAGE`.
`scripts/update-engine-pins.py` refreshes the built-in engine's pinned
packages.

## Testing loops without a real model

`crates/local/engine/chummy_engine.py --fake --port 8765` (with
`CHUMMY_ENGINE_TOKEN` set) is an OpenAI-compatible server with scripted
answers. Add it in Settings → Models as "Other OpenAI-compatible server" at
`http://127.0.0.1:8765/v1`, model `fake-model`.

## Changing things

- **New IPC command:** implement in `src-tauri/src/commands/`, add it to
  `generate_handler!` in `lib.rs` and to `build.rs`, allow it in the
  windows' `capabilities/*.json`, add a typed wrapper in `ipc.ts`, and
  commit the generated `permissions/autogenerated/*.toml`.
- **New block type:** `blocks.rs` (params, ports, catalog entry),
  `validate.rs`, `engine.rs::execute`, tests, `loopdoc.ts`, and the block table in
  `docs/dev/file-formats.md`. Blocks are text handling, model calls, flow, files in
  the jail or tools: never a script block.
- **New setting:** a field with a default in `settings.rs` (bump `VERSION`
  only for changes that need a migration), expose it in `SettingsView`,
  mirror it in `ipc.ts`, then the UI.
- **Built-in loop change:** edit the generator (`assistant.py` holds the
  shared agent loop and the Chummy assistant's prompts, `terminal.py` the
  Terminal assistant's), regenerate with `make_templates.py`, and add the
  old version's fingerprint to `RETIRED` in `src-tauri/src/library.rs` so
  unedited saved copies get upgraded. Every `templates/*.chummy.json` must be
  exactly what Chummy would save (the generator writes it that way; for the
  hand-written Blank and Simple chat, save them from Chummy or copy
  `LoopFile::to_json`): `crates/flow/build.rs` hashes the files at every build
  and those hashes are the built-in loops Chummy always trusts, so a test
  fails if a file and its fingerprint differ. A new template file also needs
  an entry in `FILES` in `templates.rs`.
- **Built-in tool change:** tools in `crates/tools/builtin/` reinstall when
  their source changes. Test their logic with
  `python3 -m unittest discover -s crates/tools/tests -p 'test_*.py'`; the
  `TerminalPromptExamples` test there runs every command the Terminal
  assistant's prompt shows, so keep it in step with `terminal.py`.

## CI and releases

- `.github/workflows/checks.yml` holds every check: frontend checks, engine
  tests, and Rust (fmt, clippy, tests).
- `ci.yml` runs them on Linux for each push and pull request.
- `ci-all.yml` ("CI (all systems)") runs them on Linux, macOS and Windows.
  Start it by hand from the Actions tab before a release, or after changing
  platform code (sandboxes, keychain, paths, the bundled Python).
- `wasi-python.yml` builds the tools' Python.
- Pushing a tag like `v0.1.2` runs `release.yml`: installers for every
  platform in a draft GitHub release. Linux builds on Ubuntu 24.04, whose
  glibc (2.39) is the oldest the packages run on. After building, the
  release takes the graphics stack out of the AppImage
  (`scripts/appimage-unbundle-graphics.sh`) so the system's Mesa never runs
  against our older copies of the libraries it shares.
