# Building and testing

## Prerequisites

- [Rust](https://rustup.rs) (version pinned in `rust-toolchain.toml`; rustup
  installs it) and Node.js 26 (what CI and releases use; 22 or newer works).
- Linux: `libwebkit2gtk-4.1-dev libayatana-appindicator3-dev librsvg2-dev
  libxdo-dev libssl-dev libdbus-1-dev build-essential`, plus a Secret
  Service (GNOME Keyring or KWallet) to save API keys.
- macOS: Xcode Command Line Tools. Windows: C++ Build Tools and WebView2.

## Commands

```sh
npm install
npm run tauri dev        # the app, with hot reload of the UI
npm run dev              # the UI alone in a browser (IPC uses mocks)
npm run tauri build      # installers: .msi/.exe, .dmg/.app, .deb/.rpm/.AppImage
npm run icons            # app icons from assets/app-icon.png
cargo build -p chummyd --release   # chummyd (not built by default)
```

chummyd is in the workspace but not in `default-members`, so `cargo build`
and the app's builds don't build it; `--workspace` (as CI uses) does. Its end
to end tests (`crates/chummyd/tests/`) skip themselves when run as root or
Administrator, which chummyd refuses. The Matrix channel is the `matrix`
feature, on by default (`--no-default-features` builds chummyd without it,
and without matrix-sdk). Its end to end test runs against a real Synapse:

```sh
python3 -m venv /tmp/synapse && /tmp/synapse/bin/pip install matrix-synapse
CHUMMY_TEST_SYNAPSE=/tmp/synapse/bin/python cargo test -p chummyd --test matrix
```

Without `CHUMMY_TEST_SYNAPSE` it's skipped.

chummyd's Docker image (`docker/chummyd/`, distroless, x86_64) builds
chummyd inside Docker, with the tools' Python taken ready-made from
`wasi-python/python-wasi.zip` (a release's, or `scripts/build-wasi-python.sh`'s;
checked against its `.sha256`). `tests/docker.rs` runs an image locked down
as the docs say:

```sh
docker build -f docker/chummyd/Dockerfile -t chummyd .
CHUMMY_TEST_IMAGE=chummyd cargo test -p chummyd --test docker
```

CI on each push checks the app and its crates only (chummyd excluded). The
**chummyd** workflow (`chummyd.yml`, started by hand, and part of "CI (all
systems)") checks chummyd: clippy with and without Matrix, no Tauri in its
dependencies, its tests (Matrix against Synapse), and its image.

Checks (CI runs all of them, and so should you before committing):

```sh
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
npm run check            # svelte-check, warnings fail
npm run test:ui          # small TypeScript tests in ui/src/lib/*.test.mts
npm run build            # Vite build
python3 -m unittest discover -s crates/local/engine
python3 crates/flow/templates/make_templates.py   # then git diff should be empty
```

## The tools' Python

Tools run on CPython built for WebAssembly, bundled with the app.
`scripts/build-wasi-python.sh` builds it from python.org's source (pinned
SHA-256 and Sigstore signature, Linux x86_64, about 5 minutes) into
`wasi-python/python-wasi.zip`. Without it the app builds but can't set up
tools. To run the sandbox tests against it:

```sh
CHUMMY_TEST_PYTHON_ZIP=$PWD/wasi-python/python-wasi.zip cargo test -p chummy-tools
```

Container tests need Docker or Podman and `CHUMMY_TEST_DOCKER_IMAGE`.
`scripts/update-engine-pins.py` refreshes the built-in engine's pinned
packages.

## Testing loops without a real model

`crates/local/engine/chummy_engine.py --fake --port 8765` (with
`CHUMMY_ENGINE_TOKEN` set) is an OpenAI-compatible server with scripted
answers. Add it in Settings → Models as "Other OpenAI-compatible server" at
`http://127.0.0.1:8765/v1`, model `fake-model`.

## Changing things

- **New IPC command:** implement in `src-tauri/src/commands/`, add it to
  `generate_handler!` in `lib.rs` and to `build.rs`, allow it in the
  windows' `capabilities/*.json`, add a typed wrapper in `ipc.ts`, and
  commit the generated `permissions/autogenerated/*.toml`.
- **New block type:** `blocks.rs` (params, ports, catalog entry),
  `validate.rs`, `engine.rs::execute`, tests, `loopdoc.ts`, and the block table in
  `docs/dev/file-formats.md`. Blocks are text handling, model calls, flow, files in
  the jail or tools: never a script block.
- **New setting:** a field with a default in `settings.rs` (bump `VERSION`
  only for changes that need a migration), expose it in `SettingsView`,
  mirror it in `ipc.ts`, then the UI.
- **Built-in loop change:** edit the generator (`assistant.py` holds the
  shared agent loop and the medium Chummy assistant's prompts and settings,
  `small.py` and `large.py` what the other two change), regenerate with `make_templates.py`, and add the
  old version's fingerprint to `RETIRED` in `crates/agent/src/library.rs` so
  unedited saved copies get upgraded. Every `templates/*.chummy.json` must be
  exactly what Chummy would save (the generator writes it that way; for the
  hand-written Blank and Simple chat, save them from Chummy or copy
  `LoopFile::to_json`): `crates/flow/build.rs` hashes the files at every build
  and those hashes are the built-in loops Chummy always trusts, so a test
  fails if a file and its fingerprint differ. A new template file also needs
  an entry in `FILES` in `templates.rs`.
- **Built-in tool change:** tools in `crates/tools/builtin/` reinstall when
  their source changes. Test their logic with
  `python3 -m unittest discover -s crates/tools/tests -p 'test_*.py'`; the
  `TerminalPromptExamples` test there runs every command the Terminal
  assistant's prompt shows, so keep it in step with `terminal.py`.

## Dependencies and versions

Every build uses exactly the versions written down in the repository, so a
release can be rebuilt the same way later:

- **Rust**: the toolchain in `rust-toolchain.toml` (rustup installs it);
  crates at the versions in `Cargo.lock` (CI builds with `--locked`).
- **npm packages**: `package-lock.json` (`npm ci`).
- **GitHub Actions**: each `uses:` names a full commit, with its version in a
  comment, so a moved tag can't change what runs. Runner images are named
  (`ubuntu-24.04`, `macos-15-intel`), not `-latest`.
- **Downloads in scripts**: by version and SHA-256 (the tools' Python and
  its build tools, appimagetool, the built-in engine's uv in
  `crates/local/src/pins.rs`); the built-in tools' packages in
  `crates/tools/builtin/pylock.*.toml`.

Keeping them current: **Dependabot** (`.github/dependabot.yml`) opens one
pull request a month each for Actions, crates and npm packages, and CI
checks it. By hand: `cargo update` (and edit `Cargo.toml` for a new major
version), `npm update`, `python3 scripts/update-engine-pins.py`, and the
versions and hashes at the top of `scripts/build-wasi-python.sh`. Update
`rust-toolchain.toml` to a new Rust a few days after its release, and the
Node version in the workflows when a new Node LTS arrives (each October).

## CI and releases

- `.github/workflows/checks.yml` holds every check: frontend checks, engine
  tests, and Rust (fmt, clippy, tests).
- `ci.yml` runs them on Linux for each push and pull request.
- `ci-all.yml` ("CI (all systems)") runs them on Linux, macOS and Windows.
  Start it by hand from the Actions tab before a release, or after changing
  platform code (sandboxes, keychain, paths, the bundled Python).
- `wasi-python.yml` builds the tools' Python.
- Pushing a tag like `v0.1.2` runs `release.yml`: installers for every
  platform in a draft GitHub release. **The tag sets the version**: before
  building, each job writes it into the app with `scripts/set-version.mjs`,
  so the app and its installers always carry the tag's version. Tags must
  be plain `vMAJOR.MINOR.PATCH` (Windows installers refuse anything else);
  a bad tag fails the release before anything builds. **The notes come from
  `CHANGELOG.md`**: the release's text starts with the section headed with
  its version (`## v0.1.5`), and a release without one stops before building.
  Write under `## Unreleased` as you go, rename it to the version in the
  commit you tag, and check with `node scripts/release-notes.mjs v0.1.5`.
  After a release,
  bring the repository's files up to date: run **Set version**
  (`set-version.yml`) from the Actions tab with the tag, which commits the
  change, or run `node scripts/set-version.mjs v0.1.3` yourself (`--check`
  only reports whether the files match). Linux builds on Ubuntu 24.04, whose
  glibc (2.39) is the oldest the packages run on. After building, the
  release takes the graphics stack out of the AppImage
  (`scripts/appimage-unbundle-graphics.sh`) so the system's Mesa never runs
  against our older copies of the libraries it shares.
